# Model browser and previews

Open **Add object** in build mode. **Original & used** combines 15 original procedural studio models with safe model references already used in the studio. **In this world** contains only references in loaded property data; it is not an HTTP directory listing or a complete inventory of the server's object path. Search filters by filename and display name. The catalog is capped at the first 500 naturally sorted references and scans at most 100,000 loaded objects; omitted or unsafe references are reported. A truncated studio catalog can omit original models too.

Explicit `.rwx` and `.x` filenames retain their format while preserving filename case. Bare stems and ZIP aliases normalize to a bare stem, retaining automatic ZIP/RWX/X lookup rather than accidentally forcing RWX. Existing saved `.rwx` references remain explicit. URLs, paths, traversal, texture filenames and unsupported CAV/motion formats are rejected by this picker. Original `wayfarer:` geometry is local-only and cannot be submitted through the picker to a remote world. The broader renderer's legacy loading behavior is a separate compatibility surface.

**Favorite** stores a model reference, not its asset bytes. Up to 64 favorites are retained without automatic eviction. **Recent** records successfully accepted Add operations, retaining the newest 32 distinct references. Undoing an Add does not remove its Recent entry. Libraries are separated by universe host, port, TLS setting, world name and object path; studio preferences have their own scope. Credentials and URL query parameters are not accepted in that scope. Corrupt preferences are preserved and do not prevent browsing or building. Storage failures are reported.

## Actual previews

Select a piece, then explicitly press **Preview model**. Selecting a row or entering a name alone does not fetch its asset. A preview shows actual original, RWX or experimental DirectX geometry with supported materials/textures (masks are RWX-specific). Dimensions use renderer model-space metres; X's unit policy remains provisional. It does not execute property actions, animate avatars or prove that the server will grant build permission. Missing textures and unsupported features appear as notices; a failed load is not replaced with a pretend thumbnail. See [DirectX support and limits](directx-models.md).

Drag inside the preview to orbit, scroll to zoom and use its reset-view button to frame the complete geometry again. One renderer/control instance is reused across preview requests. Changing universe/world scope removes the previous preview and requires a new explicit request.

Preview acceptance/retention limits are deliberately lower than the world renderer: 500,000 vertices, 2,048 parts, 16 textures, 4,096 pixels per retained image dimension and 16 megapixels of aggregate retained decoded images. The vertex/part checks run after parsing, so they do not cap peak parser memory; the parser has a separate 3-million-triangle-vertex ceiling. Image dimensions are checked after decoding; oversized images are immediately closed, but these retention limits do not bound peak decoder memory. Preview parsing is limited to 250,000 commands and 10,000 prototype invocations. The shared preview queue allows two active tasks and 32 waiting tasks; cancelled waiting jobs are removed. An in-flight bridge request cannot currently be aborted, so it retains its queue slot until it settles or reaches the existing transport timeout. Cancellation prevents further fallback URLs, stale scene updates and late image retention.

These are resource ceilings, not a promise that every model near a ceiling will be responsive. Original fixture assets and automated queue/lifecycle checks do not prove fidelity or performance for arbitrary historical worlds.

## Verification

`tests/model-library.test.ts` covers normalized aliases, deterministic catalog bounds, scope separation and storage failure preservation. `tests/model-browser-dialog.test.tsx` covers picker controls, accepted-only Recent writes, explicit preview consent, scope changes and pending-operation guards. `tests/building-ui.test.tsx` includes the full app's accepted-add/picker-close ordering regression. Preview geometry, texture ownership, cancellation, bounded queues, StrictMode and renderer reuse have separate tests in `tests/model-preview*` and `tests/preview-work-queue.test.ts`.
